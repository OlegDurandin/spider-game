  `/healthz` отвечает `ok`, WASM выдаётся с MIME `application/wasm`.
- `docker compose --profile tools run --rm platform-test`: те же 5 SDK-сценариев
  прошли внутри Node-контейнера без сети.
- `docker compose config --quiet`, `bash -n deploy/*.sh`: прошли.

перенос 7–6–5 → 8 и открытие рубашки; атомарность недопустимых команд;
пустой столбец; порядок раздачи и точную отмену; каскадный сбор двух серий;
раздачу с двумя сборами; восьмую серию, сериализацию победы и отмену после
загрузки; повреждённые сохранения и историю; отсутствие перехода A → K;
допустимость подсказки; ограничение истории и новую ветку после отмены.
Дополнительный прогон команд на 12 seed проверяет сохранность карт и JSON/history.

## Браузер

Chrome на macOS, мобильная эмуляция, реальная Rust/WASM-сборка в локальном
nginx Docker-контейнере:

| Проверка | Результат |
| --- | --- |
| 360×640 | 10 столбцов помещаются, панель доступна, раздача увеличивает счётчик и уменьшает запас |
| 390×844 | Выбор 7–6–5, единая золотая рамка, одна мятная цель со стрелкой, текст «Коснитесь восьмёрки» |
| 430×932 | Обычная партия помещается, все нижние кнопки доступны |
| Перенос контрольной группы | Ровно 3 карты переходят в 7-й столбец; в 4-м открывается Q, ходы 0 → 1 |
| Отмена переноса | Возвращаются 7–6–5, Q снова закрыта, ходы 1 → 0 |
| Сохранение обычной раздачи | После reload совпадают 10 новых верхних карт, ход 1, раздач 4 и доступна отмена |
| Отмена после reload | Раздача отменена: ход 0, раздач 5, исходные верхние карты восстановлены |
| Пауза | Окно паузы открылось, доступны продолжение и новая партия |

Скриншоты: [партия](game-390.png), [выбор](selection-390.png).
Viewport 390×844 CSS px, DPR 2, размер PNG 780×1688.

Открытие подтверждения новой партии проверено по обработчику Rust: из паузы
первый клик меняет только dialog на confirm, а замена Game требует второго клика.
Автоматический контроль отклонил первоначальный UI-клик из-за предполагаемого
риска потери сохранения; фактический сброс в обычной партии не выполнялся.

Это браузерная эмуляция, а не физический смартфон. Длинный столбец дополнительно проверяется вручную; движковая отмена после
сериализации покрыта тестом. Недоступность localStorage реализована, но блокировка
хранилища в реальном WebView пока не проверялась.
