# Паук 1.1 — повторяемые расклады, день и приглашения

## Возможности

В паузе и на экране победы доступны повтор текущего расклада, расклад дня,
приглашение другу и меню «Мои партии». Повтор требует подтверждения и сбрасывает
только текущую попытку. Лучший локальный результат для кода расклада хранится
отдельно и обновляется минимумом числа ходов: повтор, перезагрузка и отмена победы
не создают дублирующих результатов.

Старые партии v1/v2 продолжаются со своими картами и историей. У них нет достоверного
исходного seed; повтор и ссылка для них недоступны до следующей новой партии.
Публичный пример нового кода: `s1_2_0123456789abcdef`. В коде число мастей, версия
генератора и точный 64-битный seed в hex; преобразования через JS Number нет.
Алгоритм s1 использует фиксированный u64 modulo перед преобразованием к индексу,
а не размер машинного usize. Фикстуры всех 104 карт: engine/fixtures/seed-v1.json.

Выбор и назначения по-прежнему используют Game::selectable/targets/legal.
Смешанную группу нельзя поднять целиком, даже если масти одного цвета.
Действие по допустимой цели имеет приоритет над выбором её карты.

## Общий день

Смена даты: 00:00 МСК, вычисление через UTC timestamp + 10800 секунд, независимо
от локальной таймзоны. Дата фиксируется в коде `d1_YYYYMMDD` и имени слота попытки.
Вчерашняя партия остаётся в «Моих партиях», новый день открывается отдельно.

Каталог первой недели (все партии одномастные, стандартные 54 карты на столе,
50 закрытых в запасе, 10 изначально открытых карт):

| Дата МСК | Публичный расклад | Команд до победы |
| --- | --- | --- |
| 15.11.2026 | p1_0 | 159 |
| 16.11.2026 | p1_1 | 130 |
| 17.11.2026 | p1_2 | 202 |
| 18.11.2026 | p1_3 | 169 |
| 19.11.2026 | p1_4 | 137 |
| 20.11.2026 | p1_5 | 138 |
| 21.11.2026 | p1_6 | 122 |

Дальше календарь d1 повторяет ровно эти семь записей: разность дней от 15.11.2026,
остаток по модулю 7. Модуль намеренно фиксирован, а не взят от размера каталога;
добавление новых записей не должно переназначать опубликованные даты.
Код d1 и исходные p1_0..p1_6 никогда не меняются. Для нового набора можно добавить
следующие номера p1 и новую версию календаря d2 с будущей датой активации,
сохранив декодирование прежнего d1. Старые ссылки обязаны открывать прежние колоды.

Подготовка контента: собрать начальную стандартную позицию и записать допустимые
команды обычного движка. Формат файлов engine/daily/N.json: columns, stock,
solution (move: [from,start,to] либо deal: true). Начальные ID уникальны, 0..103.
Не изменять существующий файл; следующий файл добавить в catalog() и диапазон
публичных ID. Проверить прохождение через публичный ID до восьми собранных серий.

```sh
cargo run --locked -p spider-engine --example verify_catalog
cargo test --locked -p spider-engine deal::tests
```

Каталог подготовлен офлайн вспомогательным Rust-генератором find_daily; это не
сетевой решатель и не часть пользовательского интерфейса. Каждая сохранённая
запись независимо перепроверяется обычным движком, включая validate() после команды.

## Отдельные партии и сервер

Обычная партия сохраняет прежний GET/PUT /api/game и таблицу games.
Дневные: /api/game/daily_YYYYMMDD. Вызовы: /api/game/challenge_<код>.
Новая таблица game_slots имеет составной ключ Telegram ID + slot. Авторизация,
проверка структуры, лимит тела и ревизии применяются к каждому слоту отдельно.
Содержимое дневной партии/вызова должно соответствовать коду слота.

На клиенте каждый слот имеет собственную очередь отправки и кеш. Переключение
не перенаправляет незавершённый запрос в новую партию. Обычный кеш остаётся по
старому ключу; дополнительные ключи имеют суффиксы daily_/challenge_. Последний
активный слот и локальные рекорды принадлежат пространству текущего аккаунта.
В гостевом браузере та же изоляция работает через localStorage. Приглашение сначала
показывает сложность и подтверждение; неверный код не меняет активную партию.

## Ссылки и платформы

Публичная конфигурация создаётся scripts/prepare-public-config.py из разрешённых
полей .env: MINI_APP_URL, TELEGRAM_BOT_USERNAME, TELEGRAM_APP_SHORT_NAME, VK_APP_ID.
Токен не экспортируется; query/hash публичного адреса удаляются.

- Telegram: https://t.me/<bot>/<optional-app>?startapp=<код>, вход из start_param
  подписанного initData или tgWebAppStartParam. Отправка открывает выбор чата
  через официальный t.me/share/url. Реальная отправка всегда остаётся действием игрока.
- VK: https://vk.com/app<id>#/deal/<код>. Обрабатывается старт и hashchange открытого
  клиента; отправка через VKWebAppShare при наличии моста. ID может браться из
  публичной конфигурации либо vk_app_id клиента.
- Браузер: публичный HTTPS адрес с deal=<код>. Меню содержит отдельные кнопки
  отправки и копирования, а также выделяемую ссылку на случай запрета Clipboard API.

Ссылки включают только публичный код. Имя, Telegram ID, auth_date, hash, подписи
VK и текущая позиция в ссылку не попадают. Приглашение всегда начинает исходную
позицию либо явно предлагает продолжить уже начатую собственную попытку.

Официальные источники: [Telegram Mini Apps](https://core.telegram.org/bots/webapps#direct-link-mini-apps),
[Telegram share](https://core.telegram.org/widgets/share), [VK Bridge](https://github.com/VKCOM/vk-bridge).

## Проверки

Скрипт
scripts/qa/release.html предназначен только для отдельного локального origin:
он намеренно записывает синтетические гостевые партии. Не размещать на production.
Он сверяет старт WASM со всеми golden-картами, выделение смешанного хвоста,
сохранность нескольких партий и исходную позицию после повтора.

счётчик и история были нулевыми. Дневная попытка сохранила дату, ход и отмену;
после перезапуска все пять тестовых партий остались без изменений.
Повреждённый код показал ошибку и сохранил каждую ранее записанную партию.

Найденное расхождение: прежний генератор сокращал u64 до usize **до** modulo;
на native 64-bit и WASM 32-bit старт мог различаться. Для опубликованного s1
modulo выполняется в u64. Правила переноса уже соответствовали требованиям;
регрессии закреплены тестами всех режимов и проверкой точной границы выделения.
При приёмке также исправлено закрытие вложенного меню после повтора и возврата
к обычной партии; отмена повтора возвращает прямо к столу.

Telegram и VK проверены адаптерными тестами с mock SDK. Реальный выбор чата,
вход из Telegram/VK на телефоне и их системные диалоги отправки в этом прогоне
не проверялись. В Chrome проверялся браузерный запуск приглашений. Реальные
сообщения никому не отправлялись. Продолжение браузерной приёмки остановлено
ограничением Computer Use при переключении пользователем активной страницы;
непроверенные UI-сценарии (старые партии и отмена победы) покрыты Rust/API-тестами,
но не обозначены как пройденные в настоящем клиенте.
