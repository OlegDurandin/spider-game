# Стабильное поле во время хода

Раньше FLIP-анимация меняла transform самих карт внутри .table-scroll. Такие
transform расширяют scrollable overflow: при раздаче карты стартовали у нижней
кнопки, временно увеличивая область прокрутки. При изменении её границ браузер
мог корректировать прокрутку, создавая ощущение подъёма и возврата всего поля.

Теперь перенос и раздача анимируют отдельные fixed-копии за пределами скроллера.
Настоящие карты сохраняют место в раскладе через visibility:hidden и проявляются
после завершения. Отмена анимации, новая игра и сворачивание вкладки удаляют копии
и возвращают видимость. Очистка старого поколения не вмешивается в новую анимацию.
Для поля отключён overflow-anchor; scrollbar-gutter:stable сохраняет ширину при
появлении полосы прокрутки (если браузер поддерживает свойство).

## Проверка

В Docker-превью Chrome на 390×540 использован корректный расклад из 104 карт:
две длинные открытые колонки, 7–6–5 → 8, запас 50 карт, scrollTop=170.
Замер через requestAnimationFrame:

| Раздача: окончательный прирост scrollHeight | 18 px | 18 px |
| Сдвиг поля при раздаче после исправления | — | 0 px |
| Изменение scrollTop при раздаче после исправления | — | 0 px |
| Сдвиг неподвижной карты при раздаче после исправления | — | 0 px |
| Перенос касаниями: сдвиг поля / прокрутки / неподвижной карты | — | 0 / 0 / 0 px |
| Перетаскивание: сдвиг поля / прокрутки / неподвижной карты | — | 0 / 0 / 0 px |

149 px включали временный выход анимированных карт; теперь 18 px соответствуют
только одному новому ряду. Проверены завершение анимации и отмена хода. Замер
не подтвердил замену DOM-узлов столбцов, поэтому их рендер не переписывался.

Регрессионная страница: scripts/browser-jitter.html. Копировать только в отдельную
локальную копию web/dist и открывать через Docker nginx; она записывает тестовый
гостевой расклад в localStorage своего origin. Не использовать на production-origin.
«Подготовить длинный расклад» → «Начать замер» → совершить ход или раздать ряд.
Страница измеряет 15 секунд, показывает смещения по кадрам и количество оставшихся
скрытых карт/копий. При намеренной прокрутке замер сдвига тоже меняется.

Финальная сборка: после раздачи hiddenCards=0 и flightCards=0; управление снова
доступно. Проверено переключение вкладки во время следующей раздачи и возврат:
счётчик ходов корректен, кнопки доступны. Все 30 Rust-тестов и release WASM-сборка
прошли в Docker. Проверка на физическом устройстве в Telegram отдельно не выполнялась.

## Исправление регрессии перекрытия стопки

Предыдущая версия создавала fixed-копии, обходя HashMap. Порядок обхода случаен,
а z-index у копий одинаковый: ранняя по стопке карта могла перекрыть нижние.
Отдельный rotate(-4deg) усиливал впечатление раскрывания.

Копии теперь создаются в порядке карт в конечных столбцах, сверху вниз. Перенос
использует только translate с одинаковой длительностью и easing; наклон и
полупрозрачность при переносе убраны. За пределами скроллера остаётся только
визуальное движение, так что прежняя защита от изменения scrollable overflow сохранена.

В scripts/browser-jitter.html добавлена проверка правильного порядка перекрытия
и расстояний внутри движущейся стопки. В Chrome 390×540 при переносе 7–6–5:
37 кадров с копиями, stackOrderOK=true во всех кадрах, ошибка расстояния максимум
0.000031 CSS px. При перетаскивании — 40 кадров, правильный порядок во всех кадрах,
ошибка расстояния менее 0.009 CSS px (округление координат). Сдвиг поля и scrollTop
равен нулю; после завершения hiddenCards=0, flightCards=0. Все 30 Rust-тестов прошли
в Docker. Проверка на физическом Telegram WebView не выполнялась.

## Основная причина скачка при сохранении аккаунта

Прежняя проверка покрывала гостевой режим без динамической полосы аккаунта.
Дополнительный сценарий scripts/browser-layout-shift.html имитирует смену текста
«Аккаунт Telegram · прогресс сохранён» → «Сохраняем прогресс…» → исходный текст,
с видимой кнопкой переноса старой партии. Это меняло перенос строк flex-контейнера.
На прежней сборке при раздаче измерен tableShift=20.78125 CSS px и одновременно
64 flight-копии: общий сдвиг ошибочно принимался за движение каждой карты.

Исправление: полоса аккаунта имеет постоянные строки для статуса и действий,
блок подсказки — постоянную высоту с внутренней прокруткой при необходимости.
Условные кнопки и перенос текста больше не меняют размеры игрового поля.
Snapshot запоминает столбец каждой карты; геометрическая анимация запускается
только для карт, действительно сменивших столбец, или пришедших из запаса/собранных
серий. Изменение геометрии неподвижной карты не запускает перелёт.

В Chrome 390×540 тот же синтетический сценарий дал при раздаче tableShift=0,
scrollShift=0, stationaryCardShift=0, 10 flight-копий вместо 64. При переносе
7–6–5 с той же сменой статуса — нулевой сдвиг поля/прокрутки/неподвижной карты,
правильное перекрытие в 39 кадрах, погрешность расстояния <0.0001 CSS px.
Проверен возврат длинного текста после задержки 800 ms. Все 30 Rust-тестов
прошли в Docker. Сценарий эмулирует текст статуса в локальном DOM, не использует
настоящие Telegram-аккаунты и не обращается к production API.
