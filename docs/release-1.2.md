# «Пасьянс на вечер» 1.2 — Косынка

Добавлен второй Rust-движок: `engine/src/klondike.rs`. Вариант фиксирован:
сдача по одной карте, неограниченные проходы, возврат верхней карты дома на стол.
В каждой позиции ровно 52 уникальные карты. Дома: пики, черви, трефы, бубны.
Карта общая с «Пауком», для «Косынки» всегда используется полная четырёхмастная колода.

Команды — Move и Draw. Движок вычисляет selectable, legal, targets и hint;
UI использует эти же назначения для двух касаний и подсветки. Открытие рубашки
после переноса входит в один снимок отмены. Переворот сброса — отдельный ход:
`stock = reverse(waste)` с закрытием карт, без перемешивания и без возвращения
уже сыгранных карт. Следующее касание открывает первую карту нового прохода.
Пустые запас и сброс не меняют ни позицию, ни счётчик.
История ограничена прежними 100 снимками. Победа и её отмена сохраняют статус
вместе со всеми стопками; сохранение выполняется до обновления отрисовки.

## Формат и совместимость

Общий Session хранит `kind`: spider или klondike и `variant`.
Старые записи без kind принимаются как подтверждённый прежний формат «Паука»
v1/v2/v3 и проходят его существующий restore. Порядок карт и история не меняются.
Неизвестные kind, варианты, версии и повреждённые позиции отклоняются.

«Паук» сохраняет все прежние s1/p1/d1 коды и генератор. Новая «Косынка» имеет
код `k1_1_<16 hex>`: версия генератора 1, вариант сдачи по одной, точный u64 seed.
Её фиксированный shuffle использует u64 modulo перед переводом в индекс;
столбцы 1–7 раздаются с начала колоды, последняя карта оставшегося Vec — следующая
из запаса. Код никогда не переводится в JavaScript Number.
Эталоны всех 52 карт: `engine/fixtures/klondike-v1.json`, получены независимым
целочисленным расчётом. Для следующего алгоритма/варианта требуется новый код.

| Слот | Содержание |
| --- | --- |
| regular | Обычный Паук, прежний API /api/game и таблица games |
| klondike_regular | Обычная Косынка, /api/game/klondike_regular |
| daily_YYYYMMDD | Прежний дневной Паук |
| challenge_s1/p1/d1… | Прежние приглашения Паука |
| challenge_k1_1_… | Независимая Косынка по приглашению |

Именованные слоты используют существующую таблицу game_slots и прежнюю авторизацию
Telegram, ключ пользователя и отдельные ревизии/CAS. На чтении и записи проверяется,
что вид игры и публичный код соответствуют слоту. В браузере и локальном кеше та же
изоляция; очередь отправки каждого слота остаётся самостоятельной. Последний активный
стол хранится прежним ключом `.active`. Отсутствующий активный слот возвращает к
обычной партии, не создавая «Паука» внутри места «Косынки».

## Меню и стол

В компактной «Новой игре» переключатель Паук / Косынка. Масти доступны у Паука,
для Косынки показана подпись «По одной карте». До старта меняются только параметры.
Существующий обычный слот проверяется при открытии/смене выбранной игры и ещё раз
перед стартом. Предупреждение относится только к выбранному пасьянсу.

«Мои партии» подписывает каждый стол названием игры. Из Косынки вход в день назван
«Расклад дня · Паук». Дневной каталог остаётся прежним. Меню «⋯» содержит повтор,
отправку ссылки и справку «Как играть»; результат — число ходов, новая игра и вызов.
Один PublicDeal-декодер передаёт в существующие Telegram/VK/web адаптеры код
соответствующей игры. Принятие приглашения использует отдельный слот.

Стол Косынки имеет семь колонок и верхнюю строку той же сетки: запас, сброс,
промежуток, четыре дома. Длинный стол прокручивается только в игровой области;
дома и нижние кнопки остаются доступны. Общие изображения, цвета, безопасные отступы
и ограничения панелей переиспользованы. Для переполнения обе сетки резервируют
одинаковый scrollbar gutter. Выбор золотой, доступные цели отмечены стрелкой и рамкой.

## Проверки

Команды полного прогона:

```sh
cargo fmt --all --check
cargo test --workspace --locked
cargo run --locked -p spider-engine --example verify_klondike -- /tmp/spider12-fixtures
cargo run --locked -p spider-engine --example verify_catalog -- /tmp/spider12-fixtures
docker compose build web api
docker compose --profile tools run --rm --no-deps platform-test
```

Целевые сценарии движка: точный старт; альтернативные хвосты; противоположный цвет;
пустое место только для короля; открытие и его атомарная отмена; выбор между домом
и столом; возврат из дома; порядок 4♣/A♥/9♠ после сыгранного туза; несколько проходов;
перезагрузка после переворота; последняя карта и отмена победы; неуспешные команды;
валидность подсказок и сгенерированных партий; лимит истории; повреждённые записи.
Регрессии Паука и замороженный каталог также входят в полный прогон.

HTTP-проверка отдельного Docker API на localhost:8097 с вымышленным bot token:

```sh
/usr/bin/python3 scripts/release12-api-test.py /tmp/spider12-fixtures
docker restart spider12-api-qa
/usr/bin/python3 scripts/release12-api-test.py --verify
```

Пройдены два пользователя × четыре слота, миграция старого четырёхмастного Паука,
Косынка после переворота сброса, точный seed, история, конкурентная запись и ревизии.
Чужой вид игры, поддельная подпись, дублирующиеся карты и несовпадающий код вызова
отклонены. После перезапуска все восемь записей восстановились точно.
Эти проверки не запускаются на рабочих аккаунтах или базе.

Локальная оснастка для ручной браузерной приёмки: `scripts/qa/klondike.html`.
Она сохраняет фикстуры сырым JSON-текстом, сохраняя точный u64 seed; измеряет
границы выделения, обе группы целей, совпадение с golden и сохранность слотов.
Оснастка и фикстуры не входят в рабочую поставку.


### WASM и DOM

Прогоняется именно release-WASM с генерируемым загрузчиком, в изолированном
Node/jsdom, без сети и настоящего браузера. Зависимости закреплены package-lock:

```sh
docker build -f scripts/wasm-test/Dockerfile -t spider12-wasm-test .
docker run --rm --read-only --tmpfs /tmp:mode=1777 \
  -v "$PWD/web/dist:/site:ro" -v /tmp/spider12-fixtures:/fixtures:ro \
  --network none spider12-wasm-test
```

Пройдены 11 сценариев: навигация и справка, повторный запуск, перенос хвоста,
выбор между домом и столом, переворот сброса, восстановление после переворота,
победа, восстановление победы, приглашение Косынки, старая ссылка Паука,
неизвестная версия ссылки. Для каждого сценария используется новый процесс,
между перезапусками передаются только сохранения.

Итог нативного прогона: **59 тестов** (44 движка, 5 сервера, 10 клиента).
`cargo fmt --all --check`, проверка компиляции и Docker release-сборка WASM/API
успешны. Тесты платформенных адаптеров и отправки ссылок, включая точный u64
в коде Косынки, прошли с подставными SDK. Семь прежних решений каталога Паука
по-прежнему собирают 8/8 серий.

### Настоящий браузер

Ручная приёмка проведена в Chrome на macOS с игровой областью 360×640,
390×844 и 390×500 CSS px. Это браузерная проверка, а не настоящий мобильный WebView.
Горизонтального переполнения нет, сетки домов и столбцов совпадают;
все четыре дома и семь столбцов доступны.

Проверены реальные касания мышью: выбор и перенос хвоста 8♥–7♣ на 9♣,
недоступность 9♦, оба назначения для 5♦, перенос в дом и обратно,
переворот сброса и следующая карта после перезагрузки, последний король,
восстановление результата и отмена победы. Выделение совпадает с границами хвоста.
Эталонный старт приглашения совпал со всеми 52 картами native-движка.
Старый четырёхмастный Паук восстановился с историей; обычные игры, оба вида
приглашений и дневной Паук сохранились после переключений и перезагрузки.
Закрытие «Новой игры» и неверная ссылка не изменили партии;
предупреждение замены относится только к выбранному пасьянсу.
