# Пользовательские партии

Для Telegram добавлен отдельный Rust API (Axum) и SQLite. Подписанное initData
передаётся в Authorization header, без серверных сессий и без bot token в клиенте.
Проверяются HMAC-SHA256, уникальность полей, auth_date (24 часа, допуск 30 секунд
в будущее), положительный 52-битный user.id. API принимает только текущего
авторизованного пользователя, не переданный клиентом ID. Ответы не кешируются;
API-запросы не пишутся в nginx access log. В обычных логах URI не включает query.

GET /api/game → user_id, revision, game (null при первом входе).
PUT /api/game ← revision и game. Создание разрешено только при revision=0,
обновление — только при совпадении актуальной ревизии. При гонке один запрос
побеждает, второй получает 409 без перезаписи. Движок валидирует все карты и историю.
Лимит тела 2 MiB. В базе хранятся ID, партия, ревизия и время, без имени/фото пользователя.

Клиент сначала подтверждает Telegram-аккаунт и загружает серверную партию, затем
показывает стол. Кеши разных аккаунтов разделены. Отправка сериализована и объединяет
промежуточные изменения, сохраняя последнее состояние. Локальная запись содержит
базовую ревизию и dirty-флаг. Несохранённая партия восстанавливается и отправляется,
если ревизия сервера не изменилась. При конфликте локальная ветка архивируется,
а загрузка серверной партии происходит явно через кнопку или при повторном входе.
Старое анонимное сохранение никогда не присваивается аккаунту автоматически:
предлагается перенос с отдельным подтверждением. Браузерные гости сохраняются локально.

API не проверяет честность игровой стратегии: он проверяет структурную целостность
сохранения. Рейтинга, призов, общей игры и авторизации VK в этой версии нет.
Для входа Telegram нужен доступ к серверу; после входа можно продолжать при временной
потере сети, затем нажать «Повторить отправку». При истечении входа нужно переоткрыть
Mini App. Локальный кеш на общем устройстве не является защищённым хранилищем:
человек с доступом к DevTools браузера может прочитать его.

## Данные на VPS

Docker: nginx `spider-web` → API `spider-api:8082` во внутренней сети, API без ports.
Том `spider-web_user-data`, путь /data/spider.sqlite3 (WAL, synchronous FULL).
Перезапуск и пересборка образов не затрагивают том. down -v удаляет данные.
Для согласованного backup используйте SQLite backup API, а не копирование активного
.sqlite3 без WAL. В deploy/configure-api.py токен передаётся только через SSH stdin,
не попадает в argv, журналы или release tar. На сервере .env имеет права 600.

## Проверки выпуска пользовательских аккаунтов (до 1.1)

30 Rust-тестов: 19 движка, 3 серверных сценария, 5 сценариев жестов/новой игры,
3 сценария очереди отправки. Все прошли в Docker. Пять mock-сценариев адаптера
платформ также прошли. scripts/account-test.py независимо подписывает тестовый
Telegram initData Python HMAC и проверяет HTTP API с двумя синтетическими аккаунтами,
гонку двух записей, устаревшую запись, подменённый ID и повреждённую колоду.
Повторный GET после перезапуска Docker API подтвердил точное восстановление
партии, выбранных мастей и истории. Команда --backup создала согласованную копию SQLite.

Браузерный UI в этой сессии проверить не удалось: Computer Use возвращает
cgWindowNotFound при подключении к Chrome. Реальный вход двух аккаунтов внутри
Telegram на телефонах не проверялся. API-проверки используют отдельную Docker-базу
и фальшивый тестовый токен; реальные аккаунты и партии для тестов не изменялись.

Инфраструктура bots-server: коммит add9581 отправлен в main. Незавершённые изменения
других проектов в README/Caddy и каталоги evolution/wargaming сохранены вне коммита.

Резервная копия перед последующими выкладками создаётся командой:
`docker exec spider-api /usr/local/bin/spider-server --backup /data/backups/<name>.sqlite3`.
Её следует также выносить с VPS для защиты от потери всего диска.

Выкладка 2026-11-15: web `spider-web:local-bd530f8ef80e`, API
`spider-api:local-1933c7fa61c7`. Backup конфигурации:
`/opt/bots/backups/spider-20261115T064943Z`.
HTTPS-проверки подтвердили совпадение итоговых HTML/WASM и отказ 401/no-store
для запросов без входа и с поддельным пользователем. Оба контейнера healthy;
у API нет опубликованного порта. Проверена база в томе и согласованная копия перед выкладкой.

## Релиз 1.1

Обычные, дневные и приглашённые партии теперь имеют независимые очереди и ревизии.
Новые маршруты `/api/game/{slot}` используют таблицу `game_slots`; обычная партия
сохраняет прежний маршрут и таблицу. Сохранения v1/v2 нормализуются движком при чтении.
Приёмка и команды актуального релиза: [release-1.1.md](release-1.1.md).
