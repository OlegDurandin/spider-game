# Пасьянс на вечер · Паук, Косынка и Три пика

Три мобильных пасьянса на Rust, Leptos CSR и WebAssembly: «Паук» на 1, 2 и 4 масти,
«Косынка» со сдачей по одной карте, неограниченными проходами и возвратом из домов,
и «Три пика» с соседними рангами K ↔ A ↔ 2 и одним проходом запаса.
У каждой игры своя обычная партия; дневной Паук и приглашения сохраняются отдельно.
Можно продолжить последний стол, отменить до 100 ходов, повторить исходный расклад,
поделиться ссылкой и открыть справку через меню. Подсказки и доступные назначения
вычисляет Rust-движок. В Пауке также доступны перетаскивание и анимации ходов.

Партия и история сохраняются после каждого завершённого действия. В Telegram
прогресс привязан к подтверждённому аккаунту и синхронизируется с Rust API;
в браузере работает гостевой localStorage. Все рабочие сервисы развёрнуты в Docker.

## Запуск через Docker

Нужен Docker с Compose v2. На macOS сначала запустите Docker Desktop.

```bash
# Заполните TELEGRAM_BOT_TOKEN в .env
docker compose up --build -d web
# http://127.0.0.1:8080/
docker compose logs -f web
docker compose --profile tools run --rm test
docker compose --profile tools run --rm platform-test
docker compose down
```

Полный многоэтапный Dockerfile устанавливает Rust 1.95 и Trunk 0.21.14,
выполняет тесты workspace, сборку Rust API и release-сборку WASM. В web-образе nginx и
публичные файлы: пользователь nginx, read-only FS, tmpfs, без capabilities,
64 МБ RAM, healthcheck `/healthz`. `.env` исключён из Git и Docker-контекста.
Отдельный API-контейнер работает от UID 65532, без опубликованного порта, с read-only FS и
постоянным томом user-data для SQLite. Сборка WASM использует Debian Trixie: текущему Linux-бинарнику wasm-bindgen
нужна glibc не ниже 2.38. Итоговый runtime от этой сборочной системы не зависит.

Для получения статики из Docker-образа после сборки:

```bash
mkdir -p web/dist
docker compose run --rm --no-deps --entrypoint tar web -C /usr/share/nginx/html -cf - . | tar -xf - -C web/dist
```

## Rust-разработка без Docker

Этот путь удобен для локальной отладки; на VPS игра работает в Docker.
Установите стабильный Rust через [rustup](https://rustup.rs/), затем:

```bash
rustup target add wasm32-unknown-unknown
cargo install trunk --locked --version 0.21.14
cargo test
cargo fmt --all --check
node scripts/platform-test.mjs
cd web
trunk serve --locked
# http://127.0.0.1:8080/
trunk build --release --locked
# Результат: web/dist/ относительно корня репозитория.
```

Node нужен только для необязательных тестов SDK-адаптера. Игровой движок,
подсказки, состояние и UI написаны на Rust. JS только подключает SDK площадок;
загрузчик WASM генерирует Trunk. Для воспроизводимости зависимостей хранится
Cargo.lock. Первичная сборка требует доступа к crates.io и GitHub Releases.

## Telegram

В `.env` подготовлены `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`,
`MINI_APP_URL`, необязательный `VK_APP_ID`. Заполните локально; токен не должен
попадать в frontend. Rust API использует токен только для серверной проверки подписи
Telegram initData. Long Polling для игры не нужен.

В [BotFather](https://t.me/BotFather) выберите бота через `/mybots`, настройте
Main Mini App и/или Menu Button → Configure menu button. Укажите HTTPS-адрес
`https://spider.85-137-95-37.sslip.io/` и подпись кнопки «Играть».
Игра вызывает `ready()` и `expand()`,
учитывает доступную высоту и safe area. После сворачивания перечитывает сохранение.
Сторонний сбой SDK не блокирует WASM. Вход проверяется по подписанным данным запуска;
при недоступном API игра предлагает переоткрыть Telegram, не открывая чужой прогресс.

Официальная документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps).

## VK

Создайте Mini App в кабинете [VK для разработчиков](https://dev.vk.com/),
в настройках размещения укажите тот же HTTPS URL для поддерживаемых клиентов.
В обычной браузерной ссылке VK SDK не загружается; при наличии `vk_app_id`
подключается закреплённый официальный VK Bridge 2.15.11 и вызывается
`VKWebAppInit`. Обновления insets применяются к безопасным отступам.
[Исходники и API VK Bridge](https://github.com/VKCOM/vk-bridge/tree/master/packages/core).

Telegram-аккаунты имеют отдельные серверные партии и локальные кеши. Обычная браузерная
и VK-версия пока используют гостевую партию этого браузера; авторизация VK не реализована.

## Движок и сохранение

`engine/` — чистая библиотека Rust, не зависит от браузера. Карта имеет уникальный
ID 0–103; ранг выводится из ID. `Game::new(seed)` даёт воспроизводимую раздачу.
`selectable`, `legal` и `targets` используются и UI, и подсказками, и командами.
Перенос/раздача атомарны; открытия и сборы серий входят в один снимок истории.
Приоритет подсказки — сбор серии, затем открытие рубашки и соединение хвостов.
Подсказка отбирает ходы с непосредственной пользой и пропускает эквивалентные
позиции из истории. Отсутствие такой подсказки не означает отсутствие допустимых
тактических ходов; их можно выполнять вручную.

В гостевом ключе `spider.game.v1` — один JSON: версия, полное состояние, история.
Проверяются версия, все 104 уникальных ID, размеры запаса, открытость столбцов,
каждая собранная серия и снимки истории. Повреждённая запись не затирается
автоматически: сначала предлагается новая игра. При недоступном хранилище
игра остаётся доступной с предупреждением.

`/?demo=1` открывает контрольный расклад 7–6–5 → 8 для визуальной проверки;
он использует отдельный ключ `spider.demo.v1` и не заменяет обычную партию.
При перезагрузке демонстрация начинается заново.

## VPS и обновления

Схема размещения согласована с `../bots-server`: VPS `85.137.95.37`, nginx
контейнер `spider-web`, порт `127.0.0.1:8094`, Caddy на 443. Порт 80 остаётся
у ispmanager. Новый API и SQLite доступны только через nginx и внутреннюю Docker-сеть.
Токен передаётся отдельно через SSH stdin в серверный .env с правами 600; полный локальный
.env не копируется. База находится в постоянном томе, вне образов.

```bash
# Сверить/обновить только конфигурацию Паука в инфраструктурном репозитории:
/usr/bin/python3 deploy/sync_bots_server.py --repo ../bots-server
/usr/bin/python3 deploy/sync_bots_server.py --repo ../bots-server --apply
# После получения web/dist из проверенной Docker-сборки:
./deploy/deploy.sh
curl -fsS https://spider.85-137-95-37.sslip.io/healthz
```

`deploy.sh` передаёт готовую статику, исходники API и Docker-конфиги, собирает nginx
и нативный Rust API на VPS и ждёт healthy. Перед изменением сохраняет Caddy и предыдущий
образ в `/opt/bots/backups/spider-<UTC>/`. Применяет только блок Паука к живому
Caddyfile; чужие локальные незавершённые изменения не попадают на VPS.
После ошибки переключения скрипт пытается вернуть предыдущий образ и Caddy.
Первая выкладка закрепляется в `.image` по image ID. Проверяйте HTTPS после деплоя.

GitHub Actions подготовлен для публикации `ghcr.io/olegdurandin/spider-web`:
`latest` и `sha-<7 символов>` после push в main. CI в GitHub нужно отдельно
проверить после публикации коммита; локальная сборка не является прогоном Actions.
Следующий путь обновляет web-образ; образ API должен быть предварительно собран через deploy.sh:

```bash
cd ../bots-server
./bots.sh 85.137.95.37 deploy spider-web sha-<коммит>
./bots.sh 85.137.95.37 rollback spider-web
```

nginx выдаёт WASM с MIME `application/wasm`, HTML и `platform.js` без долгого
кеширования; хешированные JS/CSS/WASM кешируются как immutable. Другой статический
хостинг должен сохранять эти MIME-типы и публичные имена файлов из `web/dist`.

## Выбор мастей

Кнопка «Новая игра» открывает выбор 1, 2 или 4 мастей. Изменения применяются после подтверждения; возврат сохраняет текущую партию. Во всех режимах 104 карты и 8 серий. На карту на ранг старше можно класть любую масть; переносить группу и собирать серию K–A можно только одной масти. Числовые карты показывают один крупный символ.

Текущий формат сохранения — v3: версия, исходный идентификатор (если известен), позиция и история. Старый v1 восстанавливается как одномастный; v2 сохраняет режим на 1, 2 или 4 масти. Карты и история остаются прежними. Для v1/v2 исходный seed неизвестен, поэтому повтор и ссылка появляются со следующей новой партии. Прежний ключ localStorage сохранён.

## Несколько пользователей

[Устройство хранения, перенос старых партий и проверки](docs/accounts.md).
Telegram initData проверяется HMAC-SHA256 по официальной схеме Telegram, включая
срок действия (24 часа). ID берётся исключительно из проверенной подписи; API не
принимает ID другого пользователя в теле или URL. Сохраняются расклад, выбранные масти,
ходы и история отмен. SQLite хранит отдельную строку на Telegram ID.

Локальный кеш: `spider.telegram.<id>.v1`. Несохранённые ходы отправляются последовательно.
При конфликте устройств сервер отвечает 409 и не изменяет партию; интерфейс предлагает
загрузить серверную версию, сохранив локальную ветку в ключ `.conflict.<timestamp>`.
Прежние анонимные партии доступны для переноса только после явного подтверждения.
Запуск Telegram требует соединения с API; после входа сетевые сбои сохраняют ходы локально.
